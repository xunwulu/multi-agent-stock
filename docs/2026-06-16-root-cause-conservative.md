# 根因诊断：系统为何从不喊买（8 股 0 buy）

> 日期 2026-06-16 | 方法：三路并行深挖（决策门槛 / 评分辩论 / 代码兜底）
> 配套：[2026-06-16-validation-conservative-analysis.md](2026-06-16-validation-conservative-analysis.md)（现象层）

## 一句话结论

系统从不喊买 **不是 bug、不是数据问题，而是"层层向下拽"的保守设计**——评分天花板（≈60）几乎够不到 buy 门槛（≥60），却轻松落进 watch 区间（30-50）。8 只全 watch 是**设计必然**。

## 一、三路探员分工

| 路线 | 负责人 | 查什么 | 贡献度 |
|------|--------|--------|--------|
| A 决策门槛 | 船员亲读 trader.md | 交易员喊 buy/watch 的条件 | 高 |
| B 评分+辩论 | 探员1 | 综合分怎么算、为何卡 50、辩论为何 bear 全赢 | **高** |
| C 代码兜底 | 探员2 | 代码层有没有硬改 action | 中（土壤） |

## 二、致命的多米诺链（6 环，环环往下拽）

```
①打分表"中位档=5分" → 蓝筹分析师范范落在50分附近
        ↓
②三个分数加权平均 → 数学上向50收敛
        ↓
③研究经理覆盖：基准分 ±5 → 最多抬到55（天花板低）
        ↓
④风险经理覆盖：[-10, +5] 不对称，且明文"通常负向" → 倾向再扣分
        ↓
⑤辩论举证不对称：看多要"双向达标"，看空只要"挑出一个风险" → bear 8/8 全赢，方向偏空
        ↓
⑥trader.md："综合分 30-50 就判 watch" → 50 分的票自动进 watch
```

## 三、关键量化：天花板 vs 门槛（最致命的数字）

| 量 | 数值 | 出处 |
|----|------|------|
| 评分天花板（理论最高） | ≈60 分（50 基准 +5 研究经理 +5 风险经理） | orchestrator.py:881-883, 321, 388 |
| 评分实际值（风险经理通常扣分） | **40-57 分** | 实测 8 只 |
| **buy 需要的分数** | **≥60 分** | 确定性回退 orchestrator.py:1450；基本面"看多"档 fundamentals-analyst.md:465 |
| **watch 触发分数** | **30-50 分** | trader.md:22-23 |

**矛盾点**：分数几乎不可能到 60（天花板就是 60，且风险经理习惯往下拽），却极易落进 30-50 的 watch 区。**所以 buy 是稀有事件，watch 是常态。**

## 四、逐环证据（带行号）

### 环① 打分表中位档=5分（结构性压向 50）
- 基本面 14 项打分表，中间档统一 5 分：`skills/fundamentals-analyst.md:346-362`
- 成熟蓝筹（茅台/长江电力）增速个位数、PE 中位 → 大量维度落 5 分档 → sum≈70-80 → 映射 ≈50-57
- 技术面同理，"震荡/零轴/中性区"全是 5 分档：`skills/technical-analyst.md:188-199`
- 新闻面**起点恒为 50**：`orchestrator.py:236`

### 环②③ 加权平均 + 研究经理 ±5
- 综合分公式：`orchestrator.py:881-883`（tech×w + fund×w + news×0.15），加权平均向 50 收敛
- 研究经理用 adjusted_score 覆盖：`orchestrator.py:321-322`；delta 上限 ±5：`research-manager.md:56`

### 环④ 风险经理不对称区间（系统性偏空，最狠的一环）
- 风险调整范围 **[-10, +5]**，下跌空间是上涨的 2 倍：`skills/risk-manager.md:70-76`
- 明文："风险调整通常是负向的（发现风险→降低评分），正向调整要谨慎"：`risk-manager.md:85`
- 风险经理再覆盖一次：`orchestrator.py:388-389`

### 环⑤ 辩论举证不对称（bear 易赢）
- bull/bear 辩手 prompt **完全对称**（结构、工具、协议一致）——**不是 bull 被写弱**
- 但研究经理判胜负门槛不对称：看多要"数据更扎实+逻辑更完整"双向达标：`research-manager.md:34`；看空只要"揭示被忽略的重大风险"：`research-manager.md:35`
- 蓝筹天然利空数据多（PE 百分位/PEG/资金流/股东数），bear 论据更"显得扎实"
- 结论：是评分规则偏向挑错，不是辩手强弱

### 环⑥ trader 的 watch 门槛（临门一脚）
- `skills/trader.md:22-23`：**"综合评分在 30-50 之间 → watch"**（第 1 条 watch 条件）
- `skills/trader.md:65`："neutral → 偏保守（倾向更低目标价）"
- buy 条件（trader.md:28-30）：需"明确方向性信号" + "目标价偏离≤30%"——但 8 只方向都被环⑤拉成 neutral/bearish，方向信号不成立
- 盈亏比 2:1 不是 buy 硬门槛，而是影响 confidence 的 risk_controllability 维度：`trader.md:95`

## 五、代码层放大器（3 处，是"土壤"非"元凶"）

探员2 确认：**没有任何一行代码把已生成的 buy 硬改成 watch**（quality.py 对 action 只校验不改写；第 12 步 `buy+confidence<40` 仅 warn 不降级，`quality.py:1225-1228`）。8 只全 watch 是 **LLM trader 自己产出的**，证明元凶在 prompt 侧。

但代码层有 3 处"保守化土壤"压低了喂给 trader 的看涨分：
1. 风险经理+研究经理双重下调 score：`orchestrator.py:321-322, 388-389`
2. confidence 按风险封顶（very_high→50, high→65）：`quality.py:1143-1162`
3. governance watch/critical 给基本面打折（0.75/0.5）：`orchestrator.py:250-263`

另外 orchestrator 对 ST/治理风险股会向 trader 注入"强烈建议 watch/sell"文字（`orchestrator.py:1359-1375`）——若这 8 只触发了 governance watch，这也是一个"代码驱动的喊 watch"来源，待查。

## 六、不是 bug，是设计

这套"层层向下拽"的设计，在**避免乱喊买、防止船长追高**上是成功的（有研新材就是证明——识破追高风险）。代价是**几乎永不喊买**。

系统的世界观是"右侧防守型交易员"：宁可错过，不可做错。这不是缺陷，是性格——但需要船长知道这个性格，并决定是否要调整。

## 七、治疗方向（对应多米诺每一环，先不调，待船长定）

| 调哪环 | 做法 | 效果 | 风险 |
|--------|------|------|------|
| 环⑥ watch 门槛 | 把"30-50→watch"放宽到"30-45→watch" | 50 分的票有机会变 hold | 低 |
| 环④ 风险对称 | [-10,+5] 改成 [-7,+7] 对称 | 分数天花板抬高 | 低 |
| 环③ 研究经理 delta | ±5 放宽到 ±8 | 看涨票能上 60 | 中 |
| 环⑤ 辩论门槛 | 看空也要求"双向达标" | bear 不再总赢 | 中 |
| 价值股专项 | 对低 PE+大股东增持的票走"左侧轻仓"分支 | 长江电力类能被识别 | 高（要新逻辑） |

**推荐起手**：先调环⑥（watch 门槛）+ 环④（风险对称），这两处风险最低、见效最快，能让"50 分的票"从 watch 变 hold、让分数天花板抬到 65+，看 buy 能否出现。
