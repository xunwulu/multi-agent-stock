# TradingAgents-CN 项目研讨与学习笔记

> **整理日期**: 2026-04-21 | **参与者**: 船长（Xuesen）+ 船员（Claude/GLM-5.1） | **主题**: 项目分析 + 技术学习 + 改造方向探讨

## 一、项目深度分析

### 1.1 项目概况

**TradingAgents-CN** 是一个基于多智能体协作的 AI 股票分析学习平台（中文增强版），源自 TauricResearch/TradingAgents。

- **仓库**: https://github.com/hsliuping/TradingAgents-CN
- **当前版本**: v1.0.1
- **许可证**: 混合（核心 Apache 2.0，app/ 和 frontend/ 商业需授权）
- **代码量**: ~50,000+ 行

### 1.2 技术架构

| 层级 | 技术 |
|------|------|
| 后端 | FastAPI + Python + MongoDB + Redis |
| 前端 | Vue 3 + TypeScript + Element Plus |
| AI编排 | LangGraph + LangChain |
| LLM | 支持 12+ 家（OpenAI/DeepSeek/通义千问/Claude/Google/Ollama等） |
| 数据源 | Tushare + AKShare + BaoStock（A股）、yfinance + Finnhub（美股）、AKShare + yfinance（港股） |
| 部署 | Docker Compose（4服务：FastAPI + Vue/Nginx + MongoDB + Redis） |

### 1.3 多智能体架构

系统模拟了一个 12 人投研团队，分为 5 个团队：

| 团队 | 成员 | 职责 |
|------|------|------|
| 分析师团队（4人） | 市场分析师、基本面分析师、新闻分析师、社交媒体分析师 | 各自查数据、写分析报告 |
| 研究团队（3人） | 看多研究员、看空研究员、研究经理 | 多空辩论，经理裁决 |
| 交易员（1人） | 交易员 | 将裁决转化为买卖决策 |
| 风控团队（4人） | 激进风控、保守风控、中性风控、风控经理 | 三方辩论，经理最终决策 |
| 信号处理（1个） | 信号提取器 | 将文字决策变成结构化JSON |

**执行方式**: 全部串行，没有并发。LangGraph StateGraph 画好固定流程，Agent 按顺序执行。

### 1.4 双模型策略

- **快速模型**（quick_thinking_llm）: 分析师、研究员、风控辩论者使用，追求速度和成本
- **深度模型**（deep_thinking_llm）: 研究经理、风控经理使用，追求推理深度
- 两者可以来自不同提供商（混合模式）

### 1.5 项目评分

| 维度 | 评分(10分制) | 说明 |
|------|-------------|------|
| 架构设计 | 8.5 | 多智能体编排精巧，辩论机制创新 |
| 代码质量 | 6.5 | 部分文件过大，测试不系统 |
| 功能完整度 | 8.5 | 三市场支持、12+ LLM、6 数据源 |
| 安全性 | 5.5 | 默认密码、API Key 未加密 |
| 可维护性 | 6.0 | 三套 UI、五层配置、100+ scripts |
| 综合评分 | 7.2 | 功能强大但工程维护成本高 |

### 1.6 主要缺点

- 前后端耦合过紧，配置系统 5 层叠加过于复杂
- 三套 UI 并存（CLI / Streamlit / Vue），维护成本高
- 单文件过大（config.py 路由 2360 行，SingleAnalysis.vue 2850 行）
- 默认密码 admin/admin123，安全风险大
- 分析耗时长（2-16分钟/股），LLM 调用 30-50 次/股

## 二、技术概念学习

### 2.1 LLM 是什么

**LLM = Large Language Model = 大语言模型**

- 本质: 读了互联网上万亿字文字后，学会了"根据前面的内容预测下一个字"
- 工作方式: 一个字一个字地"接龙"，不是真的在"思考"
- 类比: 一个读过百万本书但从未出过门的书呆子，什么都能聊但算数不如计算器

**LLM vs 代码的区别**:
- LLM: "懂"语言，灵活但可能编造数据、每次回答不同、要花钱
- 代码: 不"懂"语言，死板但结果100%可复现、免费、速度快
- 对于股票分析（数据客观、指标标准、规则明确），代码比 LLM 更靠谱

### 2.2 LangGraph StateGraph 是什么

- 一个用"画图"方式编排 Agent 工作流程的工具
- 每个 Agent 是图中的一个节点，箭头是执行顺序
- 支持条件路由（if-else）和循环（辩论环节来回对话）
- 类比: 工厂流水线的传送带系统

### 2.3 API 和 SDK 是什么

- **API** = 餐厅的菜单+服务员，你点单（发请求），厨师做菜（LLM思考），服务员端结果
- **SDK** = 餐厅的专用点餐APP，帮你省去手写信点菜的麻烦
- **Claude Agent SDK** = 雇了一个会自己思考的私人助理，不是一问一答，而是自主决定要不要查数据、查几次

### 2.4 快速模型 vs 深度模型

- 类比: 实习生（快、便宜）vs 老法师（慢、贵、决策力强）
- 目的: 省钱。日常分析用实习生，关键决策请老法师
- 一次分析调 LLM 30-50 次，大部分用快速模型

### 2.5 Agent Loop（智能体循环）

来自 learn-claude-code 的核心模式，约 80 行代码:

```
while True:
    1. 模型思考，决定下一步做什么
    2. 如果模型说"我做完了" → 结束，返回结果
    3. 如果模型说"我要查数据" → 执行工具，把结果喂回去
    4. 继续循环
```

模型自己决定流程，代码只提供工具。

### 2.6 Harness 思维

来自 learn-claude-code 的核心哲学:

> **Agent 的智能（Agency）来自模型训练，不是来自代码编排。**

- 传统思维: "怎么让系统做X？" → 写代码流程
- Harness思维: "怎么让模型能够做X？" → 给模型工具和环境
- 类比: 模型是司机，Harness（代码）是汽车。司机决定往哪开，汽车提供方向盘和油门

**反模式警告**: 用 LangGraph 编排 12 个 Agent 走固定流水线，就是 learn-claude-code 批评的"提示词水管工"做法——把 LLM 塞进流水线当填空题机器。

## 三、源码深度拆解

### 3.1 每个 Agent 的真实提示词

船员提取了全部 12 个 Agent 的提示词，核心发现:

**LLM 在整个流程里只做一件事: 把数字翻译成人话，然后像人一样"辩论"。**

| Agent | 输入 | LLM做了什么 | 输出 |
|-------|------|------------|------|
| 市场分析师 | K线数据（代码获取） | 把MACD/RSI数值翻译成"多头排列""超卖区"等人话 | 技术分析报告（文字） |
| 基本面分析师 | PE/PB/ROE（代码获取） | 把数字翻译成"估值偏低""盈利能力强"等人话 | 基本面报告（文字） |
| 新闻分析师 | 新闻标题摘要（代码获取） | 判断"利好""利空" | 新闻报告（文字） |
| 看多研究员 | 4份报告 + 对手论点 | 挑好的说，反驳看空 | 买入理由 |
| 看空研究员 | 4份报告 + 对手论点 | 挑坏的说，反驳看多 | 风险警告 |
| 研究经理 | 4份报告 + 全部辩论记录 | 裁决辩论，定目标价 | 投资计划 |
| 交易员 | 投资计划 + 4份报告 | 定具体买卖策略 | 交易建议+信心分+风险分 |
| 激进风控 | 交易建议 + 4份报告 | 找理由支持冒险 | 激进观点 |
| 保守风控 | 交易建议 + 4份报告 | 找理由反对冒险 | 保守观点 |
| 中性风控 | 交易建议 + 4份报告 | 平衡两种观点 | 平衡观点 |
| 风控经理 | 全部辩论记录 | 最终拍板 | 买入/持有/卖出 |

### 3.2 辩论能不能用代码做

**结论: 能。** 股票分析的辩论是结构化的，不是开放式的:

- 辩论话题永远是那几个: PE高不高？增长行不行？技术面好不好？风险大不大？
- "反驳"的本质: 找到对方观点的关键词 → 从数据里找反面证据 → 用模板组合成反驳句
- 代码完全可以做: 规则匹配 + 模板填充 + 加权评分
- 与 LLM 辩论的差异: 代码版本稍显机械但更准确，LLM 版本更自然但可能编造数据

## 四、改造方向讨论

### 4.1 三条改造路线

| 路线 | 做法 | 成本 | 效果 | 难度 |
|------|------|------|------|------|
| 路线1: 改配置用Claude | 把 LLM 提供商从 DeepSeek 改成 Claude | 几块钱/股 | 和现在差不多但质量略高 | 极低 |
| 路线2: 算法+精简LLM | 算法做分析师，LLM只做辩论环节 | 几毛钱/股 | 保留辩论特色，省90%成本 | 中 |
| 路线3: 纯代码 | 用规则+模板替代所有LLM | 0元 | 客观准确但没有"灵气" | 中高 |

### 4.2 第四条路线: Harness 思路（最推荐）

结合 learn-claude-code 的哲学，提出的全新路线:

**不画 LangGraph 状态图，而是造一个 Harness，让模型自己做主。**

```
改造前: 50,000行代码 + LangGraph状态图 + 30-50次LLM调用
改造后: ~500行代码 + Agent Loop + 模型自己决定流程
```

核心代码就一个 while 循环:
1. 模型思考 → 决定下一步
2. 做完了 → 返回结果
3. 要查数据 → 调用工具 → 继续思考

模型可以随时换: GLM-5.1 / DeepSeek / Claude / Ollama

### 4.3 船长的实际配置验证了 Harness 思路

**重要发现**: 船长当前使用的 Claude Code 框架，实际运行的是 GLM-5.1 模型（智谱AI），不是 Claude。

```
Claude Code（框架）= 固定的，提供工具、循环、界面
GLM-5.1（模型）= 可替换的，负责思考和生成内容
```

这完美验证了 learn-claude-code 的核心观点: **框架和模型是分离的，模型可以随便换。**
